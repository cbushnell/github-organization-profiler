# Report Schema Reference

This document describes every section, field, and scoring criterion in the reports generated by `github-organization-profiler`.

## Overview

Three output formats are produced per run:

- **JSON** (`{org}_report.json`) — the canonical structured report; all sections described below refer to this schema
- **Markdown** (`{org}_report.md`) — human-readable narrative derived from the JSON; includes tables, quality rankings, and a delta section
- **CSV** (`{org}_*.csv`) — tabular exports derived from the JSON; one file per entity type (see [CSV Tables](#csv-tables))

---

## Top-Level Report Object

| Field | Type | Description |
|-------|------|-------------|
| `org` | string | Organization name |
| `generated_at` | ISO string | Timestamp of this run |
| `prev_run_at` | ISO string \| null | Timestamp of previous run; null on first run |
| `active_repo_count` | int | Number of active repositories this run |
| `dormant_repo_count` | int | Number of dormant repositories this run |
| `users` | object | Contributor profiles keyed by GitHub login |
| `repos` | object | Per-repo records keyed by repo name |
| `connections_summary` | object | Org-wide aggregated connection data |
| `delta` | object \| null | Changes vs. previous run; null on first run |

## Per-Repo Record (`repos.<name>`)

### Top-level repo fields

| Field | Type | Description |
|-------|------|-------------|
| `dormant` | bool | Whether the repo was classified as dormant this run |
| `dormant_since` | ISO date string \| null | Timestamp of last push when dormancy was first detected; null if active |

### Activity (`repos.<name>.activity`)

Source: `collectors/commits.py` (commit metrics) + `collectors/repos.py` (repo metadata)

| Field | Type | Description |
|-------|------|-------------|
| `total_commits` | int | Commits in last 6 months (180-day window) |
| `commit_frequency_30d` | int | Commits in last 30 days |
| `commit_frequency_90d` | int | Commits in last 90 days |
| `last_commit_at` | ISO string \| null | Most recent commit timestamp |
| `open_issues_count` | int | Open issues at time of collection |
| `forks_count` | int | Total fork count |
| `is_archived` | bool | Whether the repo is archived on GitHub |
| `is_fork` | bool | Whether the repo is a fork of another repo |
| `pushed_at` | ISO string \| null | Last push timestamp (carried forward for dormant repos) |

`commit_frequency_30d` and `commit_frequency_90d` are filtered subsets of the single 6-month fetch; no extra API calls are made.

### Quality (`repos.<name>.quality`)

Source: `collectors/quality.py` — a single GraphQL query per repo replaces ~6–8 REST calls.

| Field | Type | Description |
|-------|------|-------------|
| `has_license` | bool | LICENSE file detected (LICENSE, LICENSE.md, or LICENSE.txt) |
| `license_spdx` | string \| null | SPDX identifier (e.g. `MIT`, `Apache-2.0`); null if no license or unrecognized |
| `has_contributing` | bool | CONTRIBUTING.md detected (repo root or `.github/`) |
| `has_codeowners` | bool | CODEOWNERS detected (repo root or `.github/`) |
| `has_security_md` | bool | SECURITY.md detected (repo root or `.github/`) |
| `has_dependabot` | bool | Dependabot config detected (`.github/dependabot.yml` or `.yaml`) |
| `has_actions` | bool | GitHub Actions workflows present (`.github/workflows/`) |
| `action_workflows` | string[] | Names of detected workflow files |
| `issues_enabled` | bool | Issues feature enabled on the repo |
| `quality_score` | int | **0–6**: sum of the 6 boolean quality fields (see formula below) |

**Quality score formula:**

```
quality_score = has_license + has_contributing + has_codeowners
              + has_security_md + has_dependabot + has_actions
```

`license_spdx`, `action_workflows`, and `issues_enabled` are informational and excluded from the score. Active repos are sorted **ascending** by `quality_score` in the Markdown report (worst first).

### README Classification (`repos.<name>.readme_class`)

Source: `classifiers/local.py` — local keyword/rule-based classifier

| Field | Type | Description |
|-------|------|-------------|
| `category` | string \| null | One of 13 categories (see below); null if unclassified |
| `summary` | string \| null | Short description extracted from the first paragraph of the README, or the repo description if the README is empty |
| `confidence` | string | `"high"`, `"medium"`, `"low"`, or `"n/a"` (when no README and no description or topics) |

**Categories:**

| # | Category |
|---|----------|
| 1 | API / Data Service |
| 2 | CLI Tool |
| 3 | Python Library / SDK |
| 4 | Infrastructure / IaC |
| 5 | Frontend / UI |
| 6 | Design System |
| 7 | Documentation / Reference |
| 8 | Data Pipeline / ETL |
| 9 | ML / AI |
| 10 | Configuration / Shared Tooling |
| 11 | Example / Demo |
| 12 | Archive / Deprecated |
| 13 | Other |

Repos with `category = null` or `confidence = "low"` are flagged in a "Repos Needing README Attention" callout in the Markdown report. Dormant repos carry forward their cached classification without re-running the classifier.

### Connections (`repos.<name>.connections`)

Source: `collectors/connections.py`

| Field | Type | Description |
|-------|------|-------------|
| `topics` | string[] | GitHub topic tags on the repo |
| `fork_of` | string \| null | Parent repo full name (`org/repo`) if this repo is a fork; null otherwise |
| `forks` | string[] | Full names of child forks (`org/repo`) |
| `internal_package_deps` | string[] | Internal org repos this repo depends on (inferred from SBOM) |
| `reusable_workflow_refs` | string[] | Reusable workflow references found in `.github/workflows/*.yml` |

Internal dependencies are detected by fetching the repo's SBOM and matching package names against `github.com/{org}/`-prefixed entries.

## Contributors (`users.<login>`)

Source: `collectors/users.py`

| Field | Type | Description |
|-------|------|-------------|
| `name` | string \| null | Display name |
| `company` | string \| null | Company affiliation |
| `bio` | string \| null | Profile bio |
| `email` | string \| null | Public email address |
| `org_repos_contributed` | object | Per-repo contribution records keyed by repo name (see below) |

**Per-repo contribution (`users.<login>.org_repos_contributed.<repo>`):**

| Field | Type | Description |
|-------|------|-------------|
| `commits` | int | Contribution count for this repo |
| `first_commit` | null | Not collected (reserved for future use) |
| `last_commit` | null | Not collected (reserved for future use) |

---

## Connections Summary (`connections_summary`)

Source: `collectors/connections.py` — org-wide aggregations built after all per-repo data is collected.

| Field | Type | Description |
|-------|------|-------------|
| `topic_clusters` | object | Topic tag → list of repo names that share it |
| `internal_dep_graph` | object | Dependency repo → list of consumer repo names (inverted dependency graph) |

---

## Delta (`delta`)

Present only when a previous run's report exists; `null` on the first run.

| Field | Type | Description |
|-------|------|-------------|
| `repos_added` | string[] | Repo names that are new since the last run |
| `repos_removed` | string[] | Repo names that were present last run but are absent now |
| `quality_changes` | object | `{ "<repo>": { "from": int, "to": int } }` — repos whose quality score changed |
| `active_to_dormant` | string[] | Repos that became dormant this run |
| `dormant_to_active` | string[] | Repos that became active this run |
| `new_contributors` | string[] | Contributor logins seen for the first time this run |

---

## CSV Tables

Seven CSV files are exported; one row per entity pair.

| File | Key columns | Description |
|------|-------------|-------------|
| `{org}_repo_activity.csv` | repo, pushed_at, last_commit_at, commits_30d, commits_90d, open_issues_count, forks_count, is_archived, is_fork, dormant, dormant_since | Activity metrics per repo |
| `{org}_repo_quality.csv` | repo, has_license, license_spdx, has_contributing, has_codeowners, has_security_md, has_dependabot, has_actions, workflow_count, issues_enabled, quality_score, dormant | Quality signals per repo |
| `{org}_repo_classification.csv` | repo, category, summary, confidence, dormant | README classification per repo |
| `{org}_contributor_summary.csv` | login, name, company, bio, total_org_commits, org_repos_contributed, most_active_repo, first_seen, last_seen | Aggregate contributor stats |
| `{org}_repo_contributor_matrix.csv` | repo, login, commits, first_commit, last_commit, dormant | One row per (repo, contributor) pair |
| `{org}_topic_clusters.csv` | topic, repo, dormant | One row per (topic, repo) pair |
| `{org}_internal_deps.csv` | consumer_repo, dependency_repo, dormant | One row per (consumer, dependency) pair |
